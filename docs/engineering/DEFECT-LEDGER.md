# Defect Ledger - Altora Resto

Status dokumen: **AKTIF — DEFECT ARSITEKTUR DAN DESAIN TELAH DITEMUKAN**.

Ledger ini berisi temuan audit arsitektur/desain terhadap `prisma/schema/schema.prisma`
dan dokumen desain terkait (`docs/database/*.md`, `docs/api/API-CONTRACT.md`,
`docs/keamanan/PERMISSION-MATRIX.md`, `docs/engineering/MASTER-CHECKLIST.md`,
`docs/engineering/TRACEABILITY-MATRIX.md`). Belum ada kode aplikasi (service/handler)
yang diimplementasikan pada titik penulisan ulang dokumen ini — tetapi ini **tidak
berarti ledger kosong**: audit langsung terhadap skema database, kontrak API, dan
dokumen scope sudah menemukan sejumlah defect arsitektur/desain nyata (kesalahan
model data, pelanggaran batas produk, state machine tidak lengkap, relasi tenant
yang tidak aman, requirement yang hilang, kontrak API yang tidak konsisten, model
permission yang tidak memadai, dan constraint yang menghalangi kebutuhan bisnis
nyata). Defect semacam ini wajib dicatat dan diperbaiki **sebelum** implementasi
kode dimulai di domain terkait, karena memperbaikinya setelah ada data produksi jauh
lebih mahal.

Seluruh defect di bawah berstatus awal `DIKONFIRMASI` (dibuktikan langsung dari
pembacaan skema/dokumen, bukan `BARU` yang menyiratkan belum diverifikasi). **Tidak
ada satu pun defect yang boleh berstatus `DITUTUP` pada pass ini** — `DITUTUP`
membutuhkan migrasi nyata ke Postgres dan suite test integrasi/isolasi-tenant
penuh yang belum bisa dijalankan di environment ini (lihat ALT-DEF-029).
Pengecualian bersifat sebagian: ALT-DEF-012 sudah punya bukti perbaikan untuk
*gejalanya* (ukuran checklist), bukan akar masalahnya; ALT-DEF-001, ALT-DEF-002,
ALT-DEF-003, ALT-DEF-004, ALT-DEF-005, ALT-DEF-006, ALT-DEF-010, ALT-DEF-013,
ALT-DEF-007, ALT-DEF-014, ALT-DEF-015, ALT-DEF-016, ALT-DEF-017, ALT-DEF-034,
ALT-DEF-008, ALT-DEF-009, ALT-DEF-030, ALT-DEF-018, ALT-DEF-023, dan
ALT-DEF-039 sudah punya
perbaikan schema+dokumen+test struktur nyata
(correction loop 2026-07-25, lihat `docs/engineering/RELEASE-EVIDENCE.md`)
tetapi migrasi nyata dan test integrasi tenant-isolation/permission-enforcement
sungguhan belum dijalankan. Seluruhnya berstatus `SIAP_DIVERIFIKASI`, bukan
`DITUTUP`. ALT-DEF-032 adalah gap dokumen kontrak API murni (bukan schema) dan
sudah tertutup di level dokumen (`docs/api/API-CONTRACT.md` bagian 6.4) tetapi
tetap `SIAP_DIVERIFIKASI`, bukan `DITUTUP`, karena belum ada implementasi kode
untuk diverifikasi terhadapnya.

## Taksonomi Severity

- **KRITIS** — dapat menyebabkan kebocoran data tenant, merusak data transaksi,
  membuat kebutuhan utama tidak mungkin diimplementasikan, melanggar keputusan
  produk utama, atau butuh perubahan fundamental bila terlambat diperbaiki.
- **TINGGI** — menyebabkan fitur utama tidak lengkap, risiko besar pada operasional,
  perlu perubahan schema/kontrak penting, atau refactor besar bila ditunda.
- **SEDANG** — tidak memblokir fitur utama tapi menyebabkan inkonsistensi/maintenance
  buruk, perlu diperbaiki sebelum rilis.
- **RENDAH** — dokumentasi, penamaan, konsistensi minor, tidak memengaruhi
  data/workflow utama.

## Taksonomi Status

`DIKONFIRMASI` -> `SEDANG_DIPERBAIKI` -> `SIAP_DIVERIFIKASI` -> `DITUTUP`, dengan jalur
alternatif `DITUNDA_DENGAN_ALASAN` atau `TIDAK_VALID`. Nilai `BARU` dipakai hanya
untuk temuan yang belum diverifikasi langsung (tidak dipakai di ledger ini karena
semua 35 defect di bawah sudah diverifikasi langsung dari pembacaan
schema/dokumen). `TIDAK_DAPAT_DIREPRODUKSI` **tidak dipakai** untuk defect
arsitektur yang dapat dibuktikan langsung dari schema/dokumen (defect semacam ini
selalu bisa direproduksi hanya dengan membaca file, tidak butuh runtime).
